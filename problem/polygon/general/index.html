    基本信息

    题目 ID

    新建题目时，Polygon 会先要求填一个题目 ID，它用来唯一标识这道题（建议只用小写字母、数字和减号），而不是题目标题。ID 之后可以在 General Info 的 Advanced 里修改，但改掉之后旧链接会失效，所以最好一开始就想好。

    General Info

    General Info 是题目创建后进入的第一个页面，负责题目的元信息：名字、输入输出文件、时空限制、标签，以及几个高级设置。

    字段一览

    字段 含义 备注
    Input file 输入文件 stdin 表示标准输入
    Output file 输出文件 stdout 表示标准输出
    Time limit 时间限制（毫秒）
    Memory limit 空间限制（MB）
    Interactive 交互题开关 还需要准备 interactor
    Tags 标签 只影响检索，不影响评测
    Advanced 高级设置

    Input file / Output file

    输入、输出文件名。填 stdin / stdout 表示标准输入输出；填其他名字（如 sum.in、sum.out）就是文件输入输出，选手需要自己开文件读写。

    这两个值会直接进入 problem.tex 的题头（${problem.inputFile}、${problem.outputFile}），所以改了这里，题面里的输入输出说明会跟着变。

    Time limit / Memory limit

    时间限制和空间限制。Polygon 里时间限制的单位是毫秒，所以 2 秒要填 2000；problem.tex 里会除以 1000 再显示。空间限制的单位是 MB。

    Interactive

    勾选后题目变成交互题，需要在 Files 中上传交互器，并在 Interactor 界面选中。

    Tags

    题目标签，用来筛选和归档，比如标上比赛名、考察的算法。View Problems 可以按 tag 过滤，比赛里也能用 tag 管理题目。标签不影响评测，只影响检索。

    Advanced

    点击右上角的 Advanced 可以进入高级设置，下面挑几个常用的说。

    Problem name

    这里可以修改题目 ID。

    Clone

    把当前题目复制一份到自己的题库，得到一个全新的题目。适合在旧题基础上改新题，或者给别人一份可编辑的副本；原题不受影响。

    Delete

    删除题目。

    Run solutions twice

    这是通信题的开关，开启后，每份程序会在每个测试点上运行两次。具体见下文「通信题」。

    Skip duplicated tests validation

    勾选后，系统将不再检查是否有两组测试数据完全相同。大部分时候建议保持关闭。

    不同题目类型的设置方法

    普通题

    配置好输入输出和时空限制即可，其他可以保持默认。

    SPJ

    Special Judge 不在这一页配置，到 Checker 页面选择 Polygon 内置的 checker，或者上传自己写的 checker。

    交互题

    在 General Info 中勾选 Interactive，准备好交互器。评测时系统同时运行交互器和选手程序，交互器读入测试数据，按协议和选手交换信息，再把选手的输出整理后写进 tout 交给 Checker，由 Checker 判定。

    通信题

    通信题通常要借交互器实现一些功能（打乱顺序、隐藏部分信息等），所以两次运行往往都需要交互。这时要勾三处：General Info 的 Interactive（第一次运行交互）、Advanced 的 Run solutions twice（开启两次运行）和 Interactive second invocation（第二次运行也交互）。如果某一次不需要交互，就不要勾对应的选项。

    Codeforces 中通信题的原理

    两次运行是串联的：第一次运行的结果交给第二次运行，最后一次的输出交给 Checker。

    两次都交互时，第一次运行和普通交互题一样，只是交互器要把第二次运行需要的数据写进 tout，作为第二次运行的输入。之后系统再跑一次同一个交互器（所以交互器里要留标记，判断当前是第几次运行），让它和第二次运行交互，最后把选手的输出整理进 tout，交给 Checker。

    如果第一次运行不是交互，测试数据会直接喂给选手程序，它的输出作为第二次运行的输入；如果第二次运行不是交互，第一次运行的输出就直接喂给第二次运行，第二次的输出再交给 Checker。

    第一次运行可能要隐藏信息、第二次可能要打乱顺序，所以大多数情况下两次都需要交互。
