    题面

    本文记录 Polygon 题面（Statement）的编辑与渲染方式，重点是如何让题面支持中文，以及有关更高程度自定义题面的方法。

    新建题面

    进入题目页，点击上方的 Statement，选择题面语言后点击 Create，就可以逐栏填写题面了：Name 是题目标题，Legend 是题目描述，Input、Output 分别是输入、输出格式，Notes 用于样例说明等补充内容，此外还有 Scoring、Interaction 等栏目。各栏内容都按 LaTeX 语法书写，点击 In HTML 和 In PDF 可以用 HTML 和 PDF 预览题面。

    中文题面选择 Chinese 即可。如果之后还打算把题目导入 Codeforces，建议同时保留一份英文题面（实际上，你可以在英文题面里写中文，在 Codeforces 上是可以渲染的）。

    图片

    题面里要插图时，把图片传到题目 Statements 页面底部的 Statement Resource Files（不是 Files 页面里的 Resource Files，那里放的是 problem.tex、olymp.sty 这类构建资源）。上传后，在 problem.tex 里直接按文件名引用即可。

    渲染题面

    题面的渲染有两条路线，但都以 Files 里的 problem.tex 为内容来源：

    • 在 Codeforces 上打开题目时，题面由 HTML 渲染，但它只认识一部分命令：manual 里列出的排版命令（完整列表见 Statements TeX manual），加上默认 problem.tex 里用到的结构命令（\InputFile、\OutputFile、\Example、\Interaction、\Scoring、\Note）。这两类之外的命令不会被识别。数学公式交给 MathJax 渲染，公式内部的命令基本不受这份列表限制。
    • 构建 PDF 题面时（单题在 Statement 页面的 In PDF，比赛则在比赛页面构建整场题面），题面由 LaTeX 渲染。PDF 使用 Files 里的 olymp.sty 作为样式包、statements.ftl 作为总控模板。

    如果只出英文题面，默认的三个文件就够用了；如果要出中文题面，则需要分别修改这三个文件。下面逐一说明。

    单题与比赛用的不是同一份文件

    单题 PDF 使用题目 Files 页面里的 problem.tex、olymp.sty、statements.ftl；比赛 PDF 使用比赛 Properties/Files 页面里的 statements.ftl 与 olymp.sty，而 problem.tex 仍取每道题自己的。在比赛里上传额外样式文件时，文件名必须以 statements- 开头，并同步修改文件中的 \ProvidesPackage 与 statements.ftl 里的 \usepackage。

    olymp.sty

    olymp.sty 是 PDF 的样式包，负责页面尺寸与边距、页眉页脚、problem 环境（题头、样例表格）以及各章节标题的文本与字号。它默认只提供英文与俄文（新版还支持乌克兰文）的标题，也没有为通信题准备“第一次运行”“第二次运行”这类分节标题。

    为此我写了一个扩展包 olymp-addons：它不修改原本的 olymp.sty，只是在 olymp.sty 之后加载、覆盖其中的标题文本，同时补上通信题需要的分节命令。加载顺序必须是 olymp → olymp-comm → olymp-zh，否则通信题的那几个标题会被覆盖成英文；在比赛中上传时，文件名、\ProvidesPackage 和 \usepackage 三处都要加 statements- 前缀。具体用法见仓库 README。

    需要注意的是，olymp.sty 只参与 PDF 的生成。针对它的修改、以及额外上传的样式文件，都不会在渲染 HTML 时生效：HTML 只使用内置样式。因此用于生成 HTML 的题面里不能使用自己新建的 LaTeX 命令，只能用 HTML 渲染器支持的那部分命令。

    olymp.sty 还提供了一批开关，在 statements.ftl 的导言区 \def 即可改变 PDF 的显示：

    开关 作用

    编写 HTML 题面时需要注意

    前面提到，生成 HTML 题面时只会使用 Polygon 内置的样式，额外上传的扩展不参与渲染。因此通信题的 HTML 题面无法使用 olymp-comm 里定义的 \FirstRun、\SecondRun 等命令，只能自己用 \textbf{\Large{第一次运行}} 这类 LaTeX 原生命令把分节标题拼出来。

    用两份题面分别负责 PDF 和 HTML

    HTML 的命令限制意味着，一份题面很难既把 PDF 排得精致、又在 HTML 里不出错。这时可以准备两份题面：

    • Chinese 题面：正文按 PDF 的需要写，完整的 LaTeX、olymp-comm 的命令都可以用；构建 PDF 时在 Statement 页面切到它。
    • English 题面：正文同样可以写中文，但只使用 HTML 支持的命令。Codeforces 展示的是英文题面，所以 HTML 这一侧交给它。

    两份题面的正文各自独立，PDF 与 HTML 互不牵制，代价是同一份内容要维护两遍。中文题面只负责出 PDF，它的 HTML 预览不必在意。

    需要注意，problem.tex、olymp.sty、statements.ftl 是题目级资源、两种语言共用（尽管负责 HTML 预览的英文题面只需要用到 problem.tex）。

    这样中文走 PDF 专用的写法，英文走 HTML 兼容的写法，配合两份题面，两边都能正常显示。如果两边的排版要求其实一致，那一份题面就够了，不必拆成两份。

    \maketitle 输出封面，内容来自 \title、\author、\date：标题是「比赛名 + 试题册」，开头的 \vspace{4cm} 把它往下压一段；\author 与 \date 分别是出题人和比赛日期，可以按需改成具体的人名或出题组。\thispagestyle{empty} 去掉封面的页眉页脚，\setcounter{page}{0} 把封面记作第 0 页，于是正文从第 1 页开始，\pageref{LastPage} 得到的也就是正文页数（不含封面）。最后的 \clearpage 把封面页送出；随后才调用 \contest{比赛名}{地点}{日期}，设置后面各页页眉里的比赛名与日期。

    \makeproblemtable 直接在封面页上排一个两列表格：左列是题号，右列是题目名，列宽分别是 1cm 与 6cm，可以按需要调整；表格下方是「本试题册共 X 题、Y 页」和缺页提示。它没有用 figure 浮动环境，所以表格不会漂到别的页面；如果确实想让它沉到页面底部，把代码里注释掉的 \begin{figure}[b!] 与 \end{figure} 恢复即可。

    表格的内容由 \problemtitle 收集。olymp.sty 的 problem 环境本身不会调用这个宏，所以模板在导言区末尾把原环境包了一层：

    \let 先保存原来的 \problem 与 \endproblem，\renewenvironment 只是在外面加一层：进入环境时先调用 \problemtitle 登记题号与题目名，再交给原环境排版。这样既不用改动 olymp.sty，也不依赖它是否提供钩子；参数与原环境一致，第 6 个可选参数（feedback）仍然交给原环境处理。

    \problemtitle 本身只做两件事：用 \stepcounter{probcount} 递增题号（\theprobcount 把它排成 A、B、C……），再用 \protected@write 把 \addprobtotable{题号}{题目名} 写进 .aux。下一次编译读入 .aux 时，这些调用被依次执行，累积到 \probtablecontent 中，最后由 \makeproblemtable 排版。\AtEndDocument 里的 \immediate\write 则把总题数写成 \TotalProblemCount，供表格下方的「共 X 题」使用。

    也正因为内容要经过 .aux 中转，第一次编译时表格是空的、总题数显示 ?、页码是 ??，再编译一次就正常了（详见「题面导入」）。

    单题与比赛共用一份模板

    \begin{document} 之后的循环遍历所有 statement：构建比赛题面时每道题都带 path，于是打开 \ifmultistatements；构建单题时没有 path，开关保持关闭。封面、\maketitle、试题列表都放在这个开关里，所以同一份 statements.ftl 既能用于整场比赛，也能直接用于单题，不会在单题 PDF 里多出一页封面。

    题面导入

    末尾的循环负责排版所有题目：\graphicspath 让图片能在题目目录下查找，\def\ProblemIndex{...} 指定这道题在比赛中的题号，再用 \import 导入对应题目的 problem.tex；单题构建时没有 path，直接 \input。其中 \ProblemIndex 需要 olymp.sty 支持才会生效（上游版本没有用它，部分修改版会用它代替自动编号）。

    因为试题列表、总题数和页码都依赖 .aux，第一次编译时它们还是空的或显示 ??，需要再编译一次才能正确；Polygon 构建时会自动多跑一遍，本地手动构建时记得跑两遍。

    改完这些文件后，建议先在单题上构建一次 PDF，确认没有缺文件、字体和交叉引用的问题，再去构建整场比赛的题面。
